# VPN Changer — Keenetic VPN через Telegram

Один Telegram-бот управляет **любым количеством роутеров Keenetic**. Каждый пользователь
привязывает «свой» роутер и меняет WireGuard/VPN у себя, не трогая чужие.

- На роутер **ничего не устанавливается** (никаких Entware/скриптов).
- Роутер общается по HTTPS через **RCI** (Remote CLI) — работает и через `keenetic.link`,
  и по IP, и в локальной сети.
- Готовая логика RCI для WireGuard взята из открытого проекта
  [gokeenapi](https://github.com/Noksa/gokeenapi) и переписана под бота.

## Принцип работы

```
Пользователь (Telegram)
        │  /bind  →  отправляет .conf
        ▼
┌─────────────────────────┐
│  Центральный бот (VPS)  │   один бот, один токен
└─────────────────────────┘
        │  Keenetic RCI (HTTPS, challenge-response auth)
        ▼
   Keenetic роутер A ◀───── пользователь A
   Keenetic роутер B ◀───── пользователь B
   Keenetic роутер C ◀───── пользователь C
```

`/bind` проверяет доступность и авторизацию на роутере (RCI auth). При отправке
`.conf` бот скачивает файл и через `/rci/interface/wireguard/import` «загружает из
файла» конфиг — ровно как кнопка «Импортировать» в веб-интерфейсе Keenetic.

## Требования на роутере

1. HTTP/HTTPS доступ к роутеру из интернета (или KeenDNS включён).
2. Включён **CLI / Дополнительно → Доступ по командной строке (RCI)** в Keenetic,
   и пароль администратора отличается от заводского.
3. Self-signed сертификат Keenetic — по умолчанию бот отключает проверку TLS
   (`TLSSKIPVERIFY=1`). Не используйте это на роутер в недоверенной сети.

## Установка бота (на VPS или любом хосте с Docker)

```bash
cp .env.example .env
# впишите токен от @BotFather в .env
docker compose up -d --build
```

Локальный запуск без Docker:

```bash
export TG_BOT_TOKEN="123456:XXX"
go run ./cmd/bot
```

## Использование в Telegram

| Команда | Что делает |
|---|---|
| `/start` / `/help` | помощь |
| `/bind` | привязать роутер: URL, логин, пароль, имя, интерфейс |
| `/routers` | список привязанных роутеров |
| `/setiface <имя> <id>` | сменить заменяемый интерфейс (`-` = импорт нового файла) |
| `/status [имя]` | проверить связь с роутером |
| `/unbind <имя>` | отвязать роутер |
| `/admin_routers` | (админ) все роутеры всех пользователей |
| `/admin_status <ownerId> <имя>` | (админ) проверить чужой роутер |
| `/admin_unbind <ownerId> <имя>` | (админ) отвязать чужой роутер |

**Смена VPN:** пришлите боту `.conf` файл от VPN-провайдера — он будет применён
к привязанному роутеру. Если у вас несколько роутеров, укажите имя в подписи к файлу
(например «дома wifi.conf»).

**Выбор интерфейса.** При `/bind` бот показывает доступные WireGuard-интерфейсы
роутера. Укажите нужный — тогда при отправке `.conf` он заменяет именно этот
интерфейс. Если выбрать импорт (`-`), файл каждый раз добавляется как новый
(как кнопка «Импортировать» в веб-интерфейсе). Поменять позже — `/setiface`.

**Роли.** Обычные пользователи видят и меняют только свои роутеры. Владельцы из
`TG_ADMIN_IDS` управляют роутерами всех пользователей (админ-команды выше).

## Как это устроено внутри

| Файл | Назначение |
|---|---|
| `cmd/bot/main.go` | входная точка |
| `internal/keenetic/client.go` | RCI: challenge-response auth + импорт/обновление WireGuard |
| `internal/telegram/bot.go` | логика бота (bind, .conf → замена VPN) |
| `internal/store/store.go` | хранение привязок «пользователь ↔ роутер» |
| `internal/config/config.go` | переменные окружения |

### Что делает клиент RCI

- **Auth:** `GET /auth` → получает `realm`/`challenge`/cookie → `MD5(login:realm:pass)`
  → `SHA256(challenge+md5)` → `POST /auth` (как официальный Keenetic CLI).
- **Импорт:** `POST /rci/interface/wireguard/import` с base64 конфига.
- **Обновление:** разбирает `.conf` (`[Interface]`/`[Peer]`) и отправляет RCI-команды
  `interface <id> wireguard peer <key> ...` + `system configuration save`.

## Безопасность

- Токен бота и пароли роутеров хранятся в `data/state.json` (права 0600) и в `.env`.
- Только один `chat_id` видит свой роутер — изоляция по привязкам.
- Опциональный белый список пользователей: `TG_ALLOWED_IDS=123,456`. Если задан —
  бот отвечает только этим chat_id.
